What pirep ispirep이 무엇인가

You keep your notes as Markdown files in a folder. Lately you are not the only one writing to them: an agent rewrites a section, a script appends a log, a sync folder pulls in someone else's edit. Open a file a week later and you cannot tell what is new.노트를 폴더 안 마크다운으로 두고 쓰는데, 요즘은 거기 쓰는 게 나만이 아니에요. 에이전트가 한 절을 고쳐 쓰고, 스크립트가 로그를 붙이고, 동기화 폴더가 남의 수정을 끌어와요. 일주일 뒤에 열면 뭐가 새로 생긴 건지 알 수가 없어요.

pirep watches one folder and answers that question. It renders the documents properly, keeps a version every time something outside the app changes a file, and shows you a word-level diff between the version you last read and the file as it is now.pirep은 폴더 하나를 지켜보면서 그 질문에 답해요. 문서를 제대로 그려 주고, 앱 밖에서 파일이 바뀔 때마다 그 판을 보관하고, 마지막으로 읽은 판과 지금 파일을 단어 단위로 비교해서 보여줘요.

No server, no account, no cloud. The files stay in your folder; pirep only reads them.서버도 계정도 클라우드도 없어요. 파일은 폴더에 그대로 있고, pirep은 읽기만 해요.

Install설치

One line, or the dmg. The installer puts the latest release in /Applications and does not use sudo.한 줄이면 되고, dmg로도 받을 수 있어요. 설치 스크립트는 최신 릴리스를 /Applications 에 넣고 sudo를 쓰지 않아요.

TERMINAL
$ curl -fsSL https://pirep.garamnoh.workers.dev/install.sh | sh

For the dmg: download it from the latest release, open it, and drag pirep onto the Applications folder next to it.dmg로 받으려면 최신 릴리스에서 내려받아 열고, 옆에 있는 Applications 폴더로 pirep을 끌어다 놓으면 돼요.

Apple siliconM1 and later. It will not run on an Intel Mac.M1 이상만이에요. 인텔 맥에서는 돌아가지 않아요.
macOSBuilt on macOS 26, and still fine on 27.macOS 26에서 만들었고 27에서도 잘 돌아가요.
Apache 2.0The source is open and the licence is Apache 2.0.소스는 공개돼 있고 라이선스는 Apache 2.0이에요.

Building it yourself: Node.js, pnpm, Rust and the Xcode Command Line Tools, then pnpm install && pnpm tauri build.직접 빌드하려면 Node.js·pnpm·Rust·Xcode Command Line Tools 를 갖추고 pnpm install && pnpm tauri build 하면 돼요.

One folder — your Base폴더 하나 — Base

pirep watches one folder and calls it your Base. The first screen offers two ways in: New Base creates an empty folder and sets it as a Base, Open existing folder opens one that already contains markdown. Both open the native folder picker.pirep은 폴더 하나만 지켜보고, 그 폴더를 Base라고 불러요. 첫 화면에 들어가는 길이 둘 있어요. New Base는 빈 폴더를 만들어 Base로 삼고, Open existing folder는 이미 마크다운이 있는 폴더를 열어요. 둘 다 맥 기본 폴더 선택창을 띄워요.

Once a folder is picked, pirep walks the tree — skipping .pirep, node_modules, target and dot-directories — and starts watching it for changes. Your documents never move.폴더를 고르면 pirep이 그 안을 훑어요. .pirep·node_modules·target·점으로 시작하는 폴더는 건너뛰고요. 그다음부터 변화를 지켜봐요. 문서는 자리에서 움직이지 않아요.

the Base is your folder; only .pirep is pirep'sBase 는 내 폴더고, pirep 의 것은 .pirep 하나뿐이에요

You can change your Base anytime in Settings → Base → Change. The Base screen also shows whether the folder already sits in a synced location.Base는 언제든 설정 → Base → Change 에서 바꿀 수 있어요. 그 화면에서 이 폴더가 이미 동기화되는 위치인지도 알려줘요.

The reader is the point of the app, so markdown is rendered rather than approximated.읽는 화면이 이 앱의 본체예요. 그래서 마크다운을 대충 흉내 내지 않고 제대로 그려요.

tables표rendered as tables, not as pipes파이프 문자가 아니라 표로 그려요
code코드syntax highlighting문법 강조가 들어가요
maths수식KaTeXKaTeX 로 그려요
diagrams다이어그램Mermaid blocks are drawn in placeMermaid 블록을 그 자리에서 그려요
task lists할 일 목록checkboxes as checkboxes체크박스는 체크박스로 보여요
callouts콜아웃set apart from the body text본문과 구분해서 보여줘요
wiki links위키 링크[[like this]] resolve inside the Base[[이런 링크]]는 Base 안에서 연결돼요

Alongside the document there is an outline of its headings, a properties panel for its frontmatter, and Related Topics. Focus mode clears everything else away.문서 옆에는 제목 목차, frontmatter 를 보여주는 속성 칸, 그리고 관련 주제(Related Topics)가 있어요. 집중 모드를 켜면 나머지가 다 사라져요.

The sidebar — what is waiting사이드바 — 무엇이 기다리고 있나

The sidebar has two tabs: QUEUE, what is waiting to be read, and FILES, the folder as it is on disk.사이드바에는 탭이 둘 있어요. QUEUE는 읽을 것이고, FILES는 디스크에 있는 그대로의 폴더예요.

Knowledge Inboxthe landing screen, with a count of what is unread처음 열리는 화면이에요. 안 읽은 개수가 붙어요

The Knowledge Inbox itself opens with a greeting, an Updated since your last visit card, quick actions for a daily note or a note from a template, and four counts — Notes, Tags, Unread updates, Pinned.Knowledge Inbox 화면에는 인사말과 Updated since your last visit 칸, 오늘 날짜 노트나 템플릿에서 새 노트를 만드는 빠른 버튼, 그리고 숫자 넷이 있어요 — Notes · Tags · Unread updates · Pinned.

Changes — what moved while you were away바뀐 내용 — 자리를 비운 사이에 뭐가 움직였나

Every time something outside the app writes to a file in your Base, pirep keeps that version. The document then appears under Changes, and opening it shows a word-level diff between the version you last read and the file as it is now.앱 밖에서 Base 안의 파일에 무언가 쓸 때마다 pirep이 그 판을 보관해요. 그 문서는 Changes에 올라오고, 열면 마지막으로 읽은 판과 지금 파일을 단어 단위로 비교해서 보여줘요.

you decide what happens next — nothing is written back without you다음에 뭘 할지는 내가 정해요. 내가 시키지 않으면 파일에 되쓰지 않아요

step by step한 걸음씩several changes at once, or one at a time여러 변경을 한 번에 보거나, 한 걸음씩 볼 수 있어요
mark read읽음으로 표시the current file becomes the version you have read지금 파일이 '읽은 판'이 돼요
roll back되돌리기writes an older version back to the file예전 판을 파일에 다시 써요

Review changes is ⌘U. Mark as read is ⇧⌘R. Settings has a switch that marks a document read when you close it.바뀐 내용으로 가기는 ⌘U, 읽음 표시는 ⇧⌘R이에요. 문서를 닫을 때 읽음으로 표시하는 설정도 있어요.

Where the versions are kept버전이 쌓이는 곳

Inside your Base there is a .pirep folder: one copy per version, plus the change log. That folder is the only thing pirep adds to your Base. Delete it and the history goes with it — your documents are untouched.Base 안에 .pirep 폴더가 생겨요. 판마다 사본 하나씩과 변경 기록이 들어가요. pirep이 Base에 더하는 건 그 폴더 하나뿐이에요. 지우면 기록도 같이 사라지고, 문서는 그대로예요.

.pirep/versions and the change log, inside your BaseBase 안에 버전과 변경 기록이 들어가요
Settings → Version history설정 → Version historyhow long versions are kept버전을 얼마나 오래 둘지 정해요

Editing편집

⌘E opens the source of the document you are reading. It saves itself 1.2 seconds after you stop typing — there is no save button and no save shortcut to remember.⌘E를 누르면 읽고 있던 문서의 원문이 열려요. 타이핑을 멈추고 1.2초 뒤에 알아서 저장돼요. 저장 버튼도, 외울 저장 단축키도 없어요.

Editing a file is a change like any other, so pirep does not add your own edit to the Changes list — that list is for what happened outside the app.내가 고친 것도 변경이지만, Changes 목록은 앱 밖에서 일어난 일을 위한 자리예요. 그래서 내 편집은 거기 올라오지 않아요.

Files that are not markdown마크다운이 아닌 파일

A notes folder is never only markdown, so pirep opens what it finds next to it rather than sending you to another app.노트 폴더에 마크다운만 있는 경우는 없어요. 그래서 옆에 있는 파일도 다른 앱으로 보내지 않고 그 자리에서 열어요.

rendered그려서 보여줌html · htm · svg · csv · tsv · mmd — drawn in view mode, raw in edit modehtml · htm · svg · csv · tsv · mmd — 볼 때는 그려서, 고칠 때는 원문으로 보여줘요
images이미지png · jpg · jpeg · gif · webppng · jpg · jpeg · gif · webp
text and code텍스트·코드txt · json · yaml · toml · ini · sql · xml · and the usual source filestxt · json · yaml · toml · ini · sql · xml, 그리고 흔한 소스 파일들
pdfpdfopens inside the app앱 안에서 열려요

HTML slides and PDFs go full screen for presenting.HTML 슬라이드와 PDF는 전체 화면으로 띄워 발표할 수 있어요.

Where your files and data live파일과 데이터가 있는 곳

Everything is on your machine, and most of it is in the folder you chose.전부 내 컴퓨터에 있고, 대부분은 내가 고른 폴더 안에 있어요.

your documents내 문서exactly where they were — pirep never moves them out of your folder있던 자리 그대로예요. pirep이 폴더 밖으로 옮기지 않아요
.pirep/version history and the change log, inside your BaseBase 안에 버전 기록과 변경 기록이 들어가요
~/Library/WebKit/com.garamnoh.pirepthe app's own settings storage앱 설정이 여기 저장돼요

No document content leaves your machine, ever. The app has no telemetry and no sync. The only outbound request it can make is looking up the latest GitHub release, and only if you press Check for updates in Settings — that check is not finished yet and currently fails.문서 내용은 어디로도 나가지 않아요. 원격 수집도 동기화도 없어요. 밖으로 나가는 요청은 설정에서 Check for updates를 눌렀을 때 GitHub 최신 릴리스를 확인하는 것 하나뿐인데, 그 확인은 아직 완성되지 않아서 지금은 실패해요.

Removing it지우기

Drag pirep out of /Applications. Your documents are untouched — they were never anywhere else./Applications 에서 pirep을 빼면 돼요. 문서는 건드려지지 않아요. 애초에 다른 데 있던 적이 없어요.

The version history stays in .pirep inside your Base until you delete that folder yourself.버전 기록은 Base 안 .pirep 에 남아 있어요. 직접 지우기 전까지는 그대로예요.
